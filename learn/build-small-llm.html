PyTorchで小さなTransformer言語モデルを最後まで作る

このハンズオンでは、テキストを読み込み、文字をID化し、Transformerを学習し、checkpointを保存し、保存済みモデルから文章を生成します。ChatGPT級の性能を狙うのではなく、LLM学習の一連の流れを1ファイルで通します。

完成するもの

input.txt を学習データとして、文字単位のcausal language modelを学習します。数分〜数十分の学習後、学習データに似た文章を生成できる状態がゴールです。

tiny-llm/
├─ input.txt
├─ train.py
└─ checkpoint.pt

CPUでも動きます。CUDA GPUがあれば自動で使います。学習時間はデータ量とPC性能で大きく変わります。

1. 環境を作る

python -m venv .venv
# Windows
.venv\Scripts\activate

source .venv/bin/activate

Python 3.10以降を想定しています。PyTorchのGPU版は環境によってインストール方法が異なるため、GPUを使う場合はPyTorch公式のインストール案内を確認してください。

2. 学習データを置く

input.txt に、著作権や利用条件を確認できるテキストを入れます。まずは数十KB以上あると変化を観察しやすくなります。

この実装は文字単位なので、日本語でも英語でも動きます。実用LLMは通常subword tokenizerを使いますが、文字単位にするとTokenizer実装を省いてTransformerの学習ループへ集中できます。

3. 学習コードを書く

train.py を作ります。

import math
import torch
import torch.nn as nn
from pathlib import Path

# ---- hyper parameters ----
batch_size = 32
block_size = 128
embed_dim = 192
num_heads = 6
num_layers = 4
dropout = 0.1
steps = 3000
lr = 3e-4

# ---- data ----
text = Path("input.txt").read_text(encoding="utf-8")
chars = sorted(set(text))
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for ch, i in stoi.items()}

encode = lambda s: [stoi[c] for c in s if c in stoi]
decode = lambda ids: "".join(itos[i] for i in ids)

data = torch.tensor(encode(text), dtype=torch.long)
split = int(len(data) * 0.9)
train_data = data[:split]
val_data = data[split:]

device = "cuda" if torch.cuda.is_available() else "cpu"
print("device:", device, "vocab:", len(chars), "tokens:", len(data))

def get_batch(source):
    max_start = len(source) - block_size - 1
    ix = torch.randint(max_start, (batch_size,))
    x = torch.stack([source[i:i + block_size] for i in ix])
    y = torch.stack([source[i + 1:i + block_size + 1] for i in ix])
    return x.to(device), y.to(device)

class TinyLM(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, embed_dim)
        self.pos_emb = nn.Embedding(block_size, embed_dim)

        layer = nn.TransformerEncoderLayer(
            d_model=embed_dim,
            nhead=num_heads,
            dim_feedforward=embed_dim * 4,
            dropout=dropout,
            batch_first=True,
            activation="gelu",
            norm_first=True,
        )
        self.transformer = nn.TransformerEncoder(layer, num_layers=num_layers)
        self.ln = nn.LayerNorm(embed_dim)
        self.head = nn.Linear(embed_dim, vocab_size)

    def forward(self, idx, targets=None):
        b, t = idx.shape
        pos = torch.arange(t, device=idx.device)
        x = self.token_emb(idx) + self.pos_emb(pos)[None, :, :]

        # True = future tokenを見てはいけない
        mask = torch.triu(
            torch.ones(t, t, device=idx.device, dtype=torch.bool),
            diagonal=1,
        )
        x = self.transformer(x, mask=mask)
        logits = self.head(self.ln(x))

        loss = None
        if targets is not None:
            loss = nn.functional.cross_entropy(
                logits.reshape(-1, logits.size(-1)),
                targets.reshape(-1),
            )
        return logits, loss

    @torch.no_grad()
    def generate(self, idx, max_new_tokens=300, temperature=0.8):
        for _ in range(max_new_tokens):
            context = idx[:, -block_size:]
            logits, _ = self(context)
            logits = logits[:, -1, :] / temperature
            probs = torch.softmax(logits, dim=-1)
            next_id = torch.multinomial(probs, num_samples=1)
            idx = torch.cat([idx, next_id], dim=1)
        return idx

model = TinyLM(len(chars)).to(device)
optimizer = torch.optim.AdamW(model.parameters(), lr=lr)

@torch.no_grad()
def estimate_loss():
    model.eval()
    out = {}
    for name, source in [("train", train_data), ("val", val_data)]:
        losses = []
        for _ in range(30):
            x, y = get_batch(source)
            _, loss = model(x, y)
            losses.append(loss.item())
        out[name] = sum(losses) / len(losses)
    model.train()
    return out

for step in range(steps + 1):
    if step % 250 == 0:
        losses = estimate_loss()
        print(step, losses)

    x, y = get_batch(train_data)
    _, loss = model(x, y)
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()

checkpoint = {
    "model": model.state_dict(),
    "chars": chars,
    "config": {
        "block_size": block_size,
        "embed_dim": embed_dim,
        "num_heads": num_heads,
        "num_layers": num_layers,
    },
}
torch.save(checkpoint, "checkpoint.pt")

start = torch.tensor([[0]], dtype=torch.long, device=device)
out = model.generate(start, max_new_tokens=500)
print(decode(out[0].tolist()))

4. 学習する

python train.py

途中で次のようなログが出ます。

device: cuda vocab: 1432 tokens: 218450
0 {'train': 7.19, 'val': 7.21}
250 {'train': 4.12, 'val': 4.29}
500 {'train': 3.51, 'val': 3.74}
...

数値はデータで変わります。見るべきなのは絶対値ではなく、train lossとvalidation lossがどう動くかです。trainだけ下がり、valが悪化し始めるなら過学習の兆候です。

5. 何が起きているか

x は長さ128の文字ID列、y はそれを1文字ずらした正解列です。位置0では位置1の文字を、位置1では位置2の文字を当てます。causal maskによって未来の文字を参照できない状態で、全位置の次token予測を一度に学習します。

Embeddingは文字IDを192次元ベクトルに変えます。Transformer Encoderはcausal mask付きでSelf-Attentionを行い、最後のLinear層が語彙数ぶんのlogitを出します。cross entropyが「正解文字の確率をどれだけ高くできたか」を測ります。

6. checkpointから生成する

学習と生成を分けたい場合は generate.py を作ります。クラス定義と設定を共有するのが本来はきれいですが、最初はtrain.pyへ生成専用モードを足しても構いません。

checkpointに重みだけでなく、文字表とモデル構成も保存した理由は、生成時に同じID対応と同じネットワーク構造を再現する必要があるからです。

7. うまくいかないとき

症状確認すること
high >= low やbatch生成で例外input.txtがblock_sizeより十分長いか。
lossがほぼ下がらないlearning rateを1e-4〜1e-3で試す。データが極端に短くないか。
同じ文字を繰り返す学習不足、データ不足、temperatureが低すぎないか。
trainは良いがvalが悪いモデルを小さくする、dropoutを上げる、データを増やす。
GPUメモリ不足batch_size、block_size、embed_dim、num_layersを下げる。

8. 次に改造する

このモデルを少しずつ実用LLMへ近づけると、各技術の必要性が見えてきます。

  1. 文字TokenizerをBPEやSentencePieceへ置き換える。
  2. 学習率scheduleとwarmupを入れる。
  3. mixed precisionを使う。
  4. checkpointを定期保存し、途中再開できるようにする。
  5. top-k / top-p samplingを追加する。
  6. instruction形式のデータで追加学習する。
  7. 学習結果を固定評価セットで比較する。
