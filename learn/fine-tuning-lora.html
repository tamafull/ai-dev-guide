LoRAで小型モデルの振る舞いを変え、学習前後を比較する

Fine-tuningはモデルの重みを追加学習します。LoRAは巨大な重み全体を書き換えず、小さな低ランク行列だけを学習することで必要メモリを抑えます。このページでは、小型のinstruction modelに独自の回答形式を覚えさせ、学習前後を同じ入力で比較します。

完成するもの

「質問に対して必ず 要点: と 理由: の2行で答える」という小さなデータセットを作り、LoRA adapterを学習します。目的は知識を追加することではなく、出力形式や振る舞いを寄せる感覚を掴むことです。

前提

GPU推奨です。0.5B級でもCPU学習はかなり遅くなります。VRAMが少ない場合はbatch sizeやsequence lengthを下げてください。

python -m venv .venv
.venv\Scripts\activate
pip install torch transformers datasets peft accelerate

1. 小さな教師データを作る

train.jsonl:

{"prompt":"HTTP 404とは？","answer":"要点: リクエスト先のリソースが見つからないことを示すHTTPステータスです。\n理由: サーバーは要求自体を受け取ったものの、指定されたURLに対応する資源を返せませんでした。"}
{"prompt":"キャッシュの利点は？","answer":"要点: 再計算や再取得を減らし、応答時間と負荷を下げられます。\n理由: 一度得た結果を再利用できるため、同じ処理を毎回実行する必要がなくなります。"}
{"prompt":"DBインデックスとは？","answer":"要点: 特定の列を使った検索を高速化するための補助データ構造です。\n理由: 全行を順番に調べず、目的の行へ効率よく到達できるようになります。"}

実際には数十〜数千例を使います。3例は動作確認用です。

2. 学習前の出力を保存する

train_lora.py:

import json
import torch
from datasets import Dataset
from transformers import AutoTokenizer, AutoModelForCausalLM, TrainingArguments, Trainer, DataCollatorForLanguageModeling
from peft import LoraConfig, get_peft_model

MODEL = "Qwen/Qwen2.5-0.5B-Instruct"

with open("train.jsonl", encoding="utf-8") as f:
    rows = [json.loads(line) for line in f]

tokenizer = AutoTokenizer.from_pretrained(MODEL)
model = AutoModelForCausalLM.from_pretrained(
    MODEL,
    torch_dtype="auto",
    device_map="auto",
)

TEST = "DNSとは？"

def generate(m, prompt):
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt").to(m.device)
    with torch.no_grad():
        out = m.generate(**inputs, max_new_tokens=100, do_sample=False)
    generated = out[0][inputs.input_ids.shape[1]:]
    return tokenizer.decode(generated, skip_special_tokens=True)

print("BEFORE:\n", generate(model, TEST))

まずここまで実行して学習前の結果を記録します。

3. LoRA adapterを追加する

同じファイルへ続けます。

lora = LoraConfig(
    r=8,
    lora_alpha=16,
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, lora)
model.print_trainable_parameters()

出力されるtrainable parameter比率を見ると、全パラメータではなく一部だけが学習対象になっていることを確認できます。

4. Chat形式に変換してtokenizeする

def format_row(row):
    messages = [
        {"role": "user", "content": row["prompt"]},
        {"role": "assistant", "content": row["answer"]},
    ]
    return tokenizer.apply_chat_template(
        messages,
        tokenize=False,
        add_generation_prompt=False,
    )

def tokenize(batch):
    return tokenizer(
        batch["text"],
        truncation=True,
        max_length=256,
    )

ds = Dataset.from_list([{"text": format_row(r)} for r in rows])
ds = ds.map(tokenize, batched=True, remove_columns=["text"])

5. 学習する

args = TrainingArguments(
    output_dir="out",
    per_device_train_batch_size=1,
    gradient_accumulation_steps=4,
    num_train_epochs=8,
    learning_rate=2e-4,
    logging_steps=1,
    save_strategy="no",
    report_to="none",
)

trainer = Trainer(
    model=model,
    args=args,
    train_dataset=ds,
    data_collator=DataCollatorForLanguageModeling(tokenizer, mlm=False),
)

trainer.train()
model.save_pretrained("adapter")
print("AFTER:\n", generate(model, TEST))

3件だけだと過学習しやすく、未知質問への一般化も弱いです。この例ではまず「adapterを学習し、形式が寄る」ことを確認します。

6. 本当に改善したかは学習データ外で測る

次のような評価セットを別ファイルにします。

eval_prompts = [
    "TLSとは？",
    "ロードバランサの役割は？",
    "トランザクションとは？",
    "メッセージキューの用途は？",
]

for p in eval_prompts:
    print("Q:", p)
    print(generate(model, p))

「要点:」「理由:」が出る割合、内容の正しさ、余計な文章の有無を学習前後で比較します。学習データと同じ問題だけで評価すると、単なる暗記と区別できません。

7. LoRAで知識を入れるべきか

頻繁に変わる社内規定や最新製品仕様を覚えさせたいだけなら、RAGの方が更新・出典確認しやすいことがあります。Fine-tuningは次のような用途で検討しやすいです。

  • 特定の出力形式を安定させる。
  • 分類や抽出の判断パターンを大量例から学習させる。
  • 専門的なタスクの振る舞いを寄せる。
  • 短いpromptでも一定の挙動を出したい。

8. よくある失敗

失敗原因・対策
train lossだけ良くなるholdout評価を作る。データ重複を除く。
同じ文言ばかり返す例の多様性不足。少数データの過学習を疑う。
元の能力が落ちるlearning rate、epoch、LoRA rankを下げる。用途別評価を増やす。
OOM小さいモデル、短いsequence、batch 1、quantized base modelを検討する。
adapterを読み込んでも変化しないbase modelとadapterの組み合わせ、target_modules、chat templateを確認する。

9. 次に試す

  • 50〜200例へ増やし、20例をholdoutにする。
  • Prompt only / RAG / LoRAを同じ評価セットで比較する。
  • 学習データの品質を変えて性能差を見る。
  • 4bit base model + QLoRAを試し、VRAM使用量を測る。
  • adapterをmergeした場合と分離した場合の配布サイズを比べる。
