Learn · Context Engineering

Context Engineeringは「何を書くか」より「何を、いつ、どこから渡すか」を設計する

長い指示を1つ作るだけではなく、会話履歴、ファイル、検索結果、Memory、ツール出力、Skillなどを必要な場面で選び、モデルへ渡す仕組み全体を考えます。

Prompt Engineeringとの違い

Prompt Engineeringが「今回の依頼文」を整える技術だとすると、Context Engineeringは「モデルが判断するときに見えている材料全体」を設計する技術です。

典型的な工夫

  • 毎回必要なルールだけを常時コンテキストへ置く。
  • 詳細文書は必要になったときだけ検索・取得する。
  • 長時間タスクの状態は会話の外にも保存する。
  • 大量のツール定義を最初から全部読み込まない。
  • 古い情報と現在の正本を区別する。

実務例

AGENTS.mdやCLAUDE.mdへ全設計資料を詰めず、「DB変更ならこの文書」「認可変更ならこのSkill」と入口だけ置く構成は、Context Engineeringの一例です。
