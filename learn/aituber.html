Learn · AITuber

AITuberは「1つのAI」ではなく、会話ループと配信部品の組み合わせ

最小構成は、入力を受け取る → LLMが返答を作る → 音声へ変換する → アバターを動かす → OBS等で配信する、という流れです。ゲーム操作やコメント反応を足すとAgent的な構成になります。

最小構成

  1. 入力: YouTubeコメント、Twitchチャット、マイク、ゲーム状態など。
  2. 会話状態: キャラ設定、直近の会話、視聴者名、禁止事項。
  3. LLM: 次の発話や行動を決める。
  4. TTS: テキストを音声へ変換する。
  5. アバター: Live2D / 3Dモデルの口・表情・モーションを動かす。
  6. 配信: OBS等で画面・音声を合成する。

まずはゲーム操作なしで作る

最初からAIにゲームをプレイさせると、画面認識、状態管理、操作、失敗復帰まで一気に難しくなります。最初は「コメントを読む→返答→音声→口パク」だけで一周させ、その後に感情表現やToolを足す方がデバッグしやすいです。

キャラクター性はPromptだけに置かない

プロフィール、口調例、覚えてよい情報、配信ルールを別データとして持ちます。長時間配信では会話履歴をそのまま全部入れず、要約やMemoryへ整理します。

低遅延化

STT→LLM→TTSの直列構成は実装しやすい一方、待ち時間が積み上がります。ストリーミング認識、ストリーミング生成、文の途中からTTSを開始するなどで短縮できます。Realtime系の音声モデルなら一体化できる部分もあります。

アバター

Live2D CubismにはSDKとMotionSync系の仕組みがあります。既存のVTuberアプリを使う場合は、そのアプリのAPIやOSC/WebSocket等で表情・モーションを制御する構成もあります。
