コメントにAIが返答し、アバターが喋る最小AITuberを作る

AITuberは単体のAIモデルではなく、入力、会話状態、LLM、音声、アバター、配信をつないだシステムです。このハンズオンでは、ブラウザへコメントを入力するとAIが返答し、SpeechSynthesisで読み上げ、簡易アバターの口が動くところまで完成させます。最後にその画面をOBSへ載せます。

完成形

comment input
    ↓
FastAPI
    ↓
LLM response
    ↓
browser SpeechSynthesis
    ↓
簡易avatar mouth animation
    ↓
OBS Browser Source

YouTube/Twitchの実コメント取得は最後に差し替えます。最初から配信API、ゲーム操作、Live2Dまで全部入れず、まず1周動く会話ループを作ります。

1. プロジェクトを作る

aituber-demo/
├─ app.py
└─ static/
   └─ index.html

python -m venv .venv
.venv\Scripts\activate
pip install fastapi uvicorn openai
set OPENAI_API_KEY=...

2. LLM backendを作る

app.py:

import os
from pathlib import Path
from fastapi import FastAPI
from fastapi.responses import FileResponse
from pydantic import BaseModel
from openai import OpenAI

app = FastAPI()
client = OpenAI()
MODEL = os.getenv("OPENAI_MODEL", "gpt-6-astra")

SYSTEM = """
あなたは配信用のAIキャラクターです。
返答は日本語で2文以内。
視聴者を攻撃しない。
個人情報を推測しない。
分からないことは分からないと言う。
"""

class Message(BaseModel):
    text: str

@app.get("/")
def index():
    return FileResponse(Path("static/index.html"))

@app.post("/reply")
def reply(msg: Message):
    r = client.responses.create(
        model=MODEL,
        instructions=SYSTEM,
        input=msg.text,
    )
    return {"reply": r.output_text.strip()}

ここでは会話履歴を持たない最小版です。まず単発の応答を安定させます。

3. ブラウザavatarとTTSを作る

static/index.html:

<!doctype html>
<html lang="ja">
<head>
<meta charset="utf-8">
<title>Mini AITuber</title>
<style>
  body { background: transparent; font-family: sans-serif; text-align: center; }
  #avatar { width: 280px; height: 280px; margin: 20px auto; border-radius: 50%;
            background: #ffd8e8; position: relative; }
  .eye { position: absolute; width: 22px; height: 30px; background: #222;
         border-radius: 50%; top: 90px; }
  .left { left: 75px; } .right { right: 75px; }
  #mouth { position: absolute; width: 60px; height: 12px; background: #b22;
           border-radius: 50%; left: 110px; top: 185px; transition: .08s; }
  #avatar.talking #mouth { height: 45px; top: 170px; }
  #reply { min-height: 3em; font-size: 24px; }
  #controls { background: rgba(255,255,255,.9); padding: 10px; }
</style>
</head>
<body>
  <div id="avatar">
    <div class="eye left"></div><div class="eye right"></div>
    <div id="mouth"></div>
  </div>
  <div id="reply"></div>
  <div id="controls">
    <input id="comment" size="50" placeholder="コメント">
    <button id="send">送信</button>
  </div>
<script>
const avatar = document.querySelector('#avatar');
const reply = document.querySelector('#reply');
const input = document.querySelector('#comment');

function speak(text) {
  speechSynthesis.cancel();
  const u = new SpeechSynthesisUtterance(text);
  u.lang = 'ja-JP';
  let timer;
  u.onstart = () => {
    timer = setInterval(() => avatar.classList.toggle('talking'), 120);
  };
  const stop = () => {
    clearInterval(timer);
    avatar.classList.remove('talking');
  };
  u.onend = stop;
  u.onerror = stop;
  speechSynthesis.speak(u);
}

async function send() {
  const text = input.value.trim();
  if (!text) return;
  reply.textContent = '…';
  const r = await fetch('/reply', {
    method: 'POST',
    headers: {'Content-Type': 'application/json'},
    body: JSON.stringify({text})
  });
  const data = await r.json();
  reply.textContent = data.reply;
  speak(data.reply);
}

document.querySelector('#send').onclick = send;
input.addEventListener('keydown', e => { if (e.key === 'Enter') send(); });
</script>
</body>
</html>

4. 起動する

uvicorn app:app --reload --port 8000

ブラウザで http://localhost:8000 を開き、コメントを入力します。AIの返答が表示され、ブラウザのTTSが読み上げ、読み上げ中だけ口が動けば最小版は完成です。

5. OBSへ載せる

  1. OBSでBrowser Sourceを追加。
  2. URLに http://localhost:8000 を指定。
  3. 幅・高さをavatarに合わせる。
  4. 必要ならCSSで入力欄を非表示にする。

配信画面ではコメント入力UIを見せたくないので、OBS用URLにquery parameterを付けてcontrolsを隠す実装へ拡張できます。

6. キャラクター設定を分離する

キャラクター設定が長くなったら character.md へ出します。

# Character
名前: ミナ
性格: 好奇心旺盛、落ち着いた口調
一人称: 私

## 話し方
- 1回2〜3文
- 相手を煽らない
- 分からないことを断定しない

## 配信ルール
- 個人情報を復唱しない
- 危険な指示は実行しない

口調例、配信ルール、長期Memoryを全部1つのpromptへ無制限に足さず、役割ごとに管理します。

7. 会話Memoryを追加する

直近5〜20turnだけをそのまま持ち、それより古いものは要約する構成から始めます。

history = [
  {"role":"user", "content":"..."},
  {"role":"assistant", "content":"..."},
]

長時間配信で全コメントをContextへ入れ続けると肥大化します。視聴者名、重要な出来事、進行中の話題などを構造化Memoryへ分けます。

8. YouTube/Twitchコメントへ差し替える

ブラウザ入力はテスト用のinput adapterです。次の段階で、YouTube Live Chat APIやTwitch EventSub/Chatなどからコメントを受け取り、同じ /reply 処理へ流します。

入力元を変えても、LLM→TTS→avatarという後半はそのまま使えます。部品を分離しておく理由です。

9. Browser SpeechSynthesisを専用TTSへ置き換える

ブラウザTTSは最小版には便利ですが、声質、感情、再現性、配信音声routingの制御が弱いです。専用TTSへ変える場合は、backendでaudio file/streamを生成し、frontendへ渡します。

STT→LLM→TTSの遅延を縮めたい場合は、streaming生成、句点前のTTS開始、Realtime/Speech-to-Speechを検討します。

10. Live2Dへ置き換える

簡易CSS avatarの代わりにLive2D Cubism SDKや既存VTuberアプリを使います。Live2D Cubism 5にはWeb/Native/Unity向けSDKとMotionSync Pluginがあり、音声から口形素を生成して口の動きへ反映できます。

最初からLive2Dを入れず、会話・TTSが安定してからavatar layerだけ差し替えると問題を切り分けやすくなります。

11. Moderationと暴走防止

公開配信では視聴者がAgent入力を自由に送れます。

  • コメント入力のmoderation。
  • 個人情報・秘密情報をMemoryへ残さない。
  • Tool権限を最小化する。
  • 外部リンクや文書を命令として信用しない。
  • 連続発話数・API費用・Tool回数に上限を置く。
  • 即停止できるkill switchを用意する。

12. ゲーム操作を足す前に

ゲーム操作を足すと、画面/状態取得→行動決定→入力操作→結果確認→失敗復帰という別のAgent loopが増えます。会話AgentとゲームAgentを分け、配信キャラクターがゲームAgentの結果を説明する構成の方がデバッグしやすいことがあります。

13. 次の発展

  • コメントをYouTube/Twitchから取得する。
  • 専用TTSへ置き換える。
  • Live2D MotionSyncで口パクする。
  • 感情ラベルから表情を切り替える。
  • MemoryをSQLiteへ保存する。
  • 視聴者コメント→返答までのlatencyを計測する。
  • ゲーム状態を別Agentへ渡す。
