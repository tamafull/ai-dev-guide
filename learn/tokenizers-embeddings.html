文章がtoken IDとベクトルへ変わるところを実際に見る

LLMは文字列をそのまま計算しません。まずTokenizerが文字列をtoken ID列へ変換し、そのIDをEmbeddingでベクトルへ変換します。このページでは日本語・英語・コード・絵文字の分割差と、文章Embeddingの類似度を実測します。

環境

python -m venv .venv
.venv\Scripts\activate  # Windows
# source .venv/bin/activate
pip install transformers sentence-transformers torch

1. Tokenizerで同じ文章を分割する

Hugging FaceのTokenizerを使います。モデルごとにTokenizerが違うため、同じ文章でもtoken数は変わります。

from transformers import AutoTokenizer

model_name = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(model_name)

samples = [
    "今日は良い天気です。",
    "The weather is nice today.",
    "def hello(name): return f'Hello {name}'",
    "LLM🤖とRAG🔎を試す",
]

for text in samples:
    ids = tok.encode(text, add_special_tokens=False)
    pieces = [tok.decode([i]) for i in ids]
    print("TEXT:", text)
    print("IDS :", ids)
    print("TOKENS:", pieces)
    print("COUNT:", len(ids))
    print()

「単語数」とtoken数は一致しません。日本語1文字が必ず1tokenになるわけでも、英単語1個が必ず1tokenになるわけでもありません。

2. token数がなぜ実用上重要か

token数は少なくとも次の4点へ影響します。

  • コンテキスト上限に何文字入るか。
  • APIの入力・出力コスト。
  • 推論時間とメモリ使用量。
  • chunkを切るときの実際の長さ。

RAGで「500文字ずつ」に切っても、言語や内容によってtoken数は大きく変わります。実装では文字数ではなく、実際に使うTokenizerでtoken数を測る方が安全です。

3. 自分でBPEの雰囲気を観察する

同じ語を少しずつ変えて分割を比較します。

words = [
    "engineering",
    "engineer",
    "engineered",
    "context engineering",
    "context-engineering",
]

for text in words:
    ids = tok.encode(text, add_special_tokens=False)
    print(text, [tok.decode([i]) for i in ids])

Tokenizerは辞書で単語を引くだけではなく、学習済みのsubword単位へ分割します。頻出パターンは大きな単位、珍しい文字列は細かい単位になりやすくなります。

4. Embeddingで文章をベクトルへ変える

次は検索向けEmbeddingを使い、意味が近い文のcosine similarityを測ります。

from sentence_transformers import SentenceTransformer
import numpy as np

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

sentences = [
    "猫がソファで寝ている",
    "ソファの上で猫が眠っている",
    "新しいGPUで機械学習を高速化する",
    "犬が公園を走っている",
]

vectors = model.encode(sentences, normalize_embeddings=True)
sim = vectors @ vectors.T

print(np.round(sim, 3))

対角線は自分自身なので1です。「猫がソファで寝ている」と「ソファの上で猫が眠っている」は、語順や表面文字列が違っても比較的高い類似度になるはずです。

5. 5行の意味検索を作る

docs = [
    "返品は商品到着から14日以内です",
    "パスワードを忘れた場合は再設定メールを送れます",
    "請求書は毎月1日に発行されます",
    "配送状況は注文履歴から確認できます",
]

doc_vecs = model.encode(docs, normalize_embeddings=True)

def search(query, k=2):
    q = model.encode([query], normalize_embeddings=True)[0]
    scores = doc_vecs @ q
    order = np.argsort(scores)[::-1][:k]
    return [(float(scores[i]), docs[i]) for i in order]

print(search("荷物が今どこにあるか知りたい"))

これだけで簡単なsemantic searchになります。RAGはこの検索結果をLLMへ渡して回答させる構成です。

6. Embeddingは「意味そのもの」ではない

近いベクトルだから必ず正しい検索結果とは限りません。数値、否定、固有名詞、日付、似た定型文では誤ることがあります。実用RAGではkeyword search、metadata filter、rerankerなどを組み合わせることがあります。

次の文を追加して類似度を確認してみてください。

"返品は商品到着から14日以内です"
"返品は商品到着から14日以内ではありません"

否定だけが違う2文がかなり近くなる可能性があります。Embeddingの距離と論理的な同一性は別です。

7. 可視化してみる

Embeddingは数百次元ありますが、PCAで2次元に落として位置関係を見ることもできます。

pip install scikit-learn matplotlib

from sklearn.decomposition import PCA
import matplotlib.pyplot as plt

xy = PCA(n_components=2).fit_transform(vectors)
for i, (x, y) in enumerate(xy):
    plt.scatter(x, y)
    plt.text(x, y, str(i))
plt.show()

2次元化で情報は失われるため、図上の距離をそのまま本来の距離だとは考えません。用途は直感を掴むことです。
