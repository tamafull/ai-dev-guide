Learn · LLM Security

LLMに「無視して」と書くだけでは、安全境界にならない

外部Web、メール、文書、Toolを扱うAgentでは、悪意ある文章も同じコンテキストへ入ってきます。Prompt Injectionを完全にプロンプトだけで防ぐのは難しいため、権限・承認・出力検証をモデルの外側にも置きます。

代表的なリスク

  • Prompt Injection: 外部データ内の命令に誘導される。
  • 過剰権限: 読むだけでよいAgentが削除や送信までできる。
  • 安全でない出力利用: LLM出力を検証せずSQLやshellへ渡す。
  • 秘密情報の漏えい: Toolやログから不要な情報を出す。
  • Supply Chain: Skill、Plugin、MCP、モデル等の依存物が攻撃経路になる。

基本対策

最小権限、読み取りと書き込みの分離、重要操作の承認、構造化されたTool schema、出力検証、監査ログ、kill switchを組み合わせます。

学習用には安全なラボを使う

OWASPはLLMアプリ向けTop 10や、脆弱性を体験する教材を公開しています。攻撃を試す場合は、本番サービスや第三者システムではなく、明示的な学習環境だけで行います。
