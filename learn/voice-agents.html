ブラウザで話しかけると、そのまま音声で返すVoice Agentを作る

音声AIはSTT→LLM→TTSだけではありません。Realtimeでは音声を直接扱い、割り込みやturn-takingを含む会話を1sessionで処理できます。このハンズオンでは、serverで短寿命client secretを発行し、browserからWebRTCでRealtime sessionへ接続します。

完成するもの

voice-agent/
├─ server.mjs        # API keyを保持しclient secretを発行
├─ src/
│  └─ main.ts        # RealtimeAgent / RealtimeSession
├─ index.html
└─ package.json

Startボタンを押すとマイクが有効になり、話した内容へVoice Agentが音声で返答します。標準API keyはbrowserへ渡しません。

1. Vite projectを作る

npm create vite@latest voice-agent -- --template vanilla-ts
cd voice-agent
npm install
npm install @openai/agents zod openai express cors

Node.jsは現行LTSを使ってください。

2. serverでephemeral client secretを作る

server.mjs:

import express from "express";
import cors from "cors";
import OpenAI from "openai";

const app = express();
app.use(cors({ origin: "http://localhost:5173" }));

const client = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

app.get("/token", async (_req, res) => {
  try {
    const secret = await client.realtime.clientSecrets.create({
      expires_after: { anchor: "created_at", seconds: 600 },
      session: {
        type: "realtime",
        model: "gpt-realtime-2.1",
        instructions: "日本語で簡潔に会話してください。聞き取れない時は推測せず聞き返してください。",
      },
    });

    res.json({ value: secret.value, expires_at: secret.expires_at });
  } catch (e) {
    console.error(e);
    res.status(500).json({ error: "failed to create client secret" });
  }
});

app.listen(3001, () => console.log("token server: http://localhost:3001"));

client secretはbrowser/mobile向けの短寿命credentialです。通常のAPI keyをfrontendへ埋め込まないでください。

3. Browser側のAgentを書く

src/main.ts:

import { RealtimeAgent, RealtimeSession } from "@openai/agents/realtime";
import "./style.css";

document.querySelector<HTMLDivElement>("#app")!.innerHTML = `
  <h1>Voice Agent</h1>
  <button id="start">Start</button>
  <button id="stop" disabled>Stop</button>
  <p id="status">disconnected</p>
`;

const status = document.querySelector<HTMLParagraphElement>("#status")!;
const start = document.querySelector<HTMLButtonElement>("#start")!;
const stop = document.querySelector<HTMLButtonElement>("#stop")!;

const agent = new RealtimeAgent({
  name: "Japanese Voice Assistant",
  instructions: "日本語で自然に会話する。返答は短め。分からない時は聞き返す。",
});

let session: RealtimeSession | null = null;

start.onclick = async () => {
  status.textContent = "getting token...";
  const token = await fetch("http://localhost:3001/token").then(r => r.json());

  session = new RealtimeSession(agent, {
    model: "gpt-realtime-2.1",
  });

  status.textContent = "connecting...";
  await session.connect({ apiKey: token.value });
  status.textContent = "connected — speak now";
  start.disabled = true;
  stop.disabled = false;
};

stop.onclick = () => {
  session?.close();
  session = null;
  status.textContent = "disconnected";
  start.disabled = false;
  stop.disabled = true;
};

BrowserではRealtimeSessionがWebRTCを使い、マイク入力と音声再生を扱います。初回はbrowserのマイク権限確認が出ます。

4. 起動する

terminalを2つ開きます。

# terminal 1
set OPENAI_API_KEY=...
node server.mjs

# terminal 2
npm run dev

ViteのURLを開き、Startを押して話します。音声応答が返れば最小Voice Agentは完成です。

5. うまく動かない時

症状確認
マイクが使えないbrowser site permission、OS microphone permission、HTTPS/localhost条件。
401/403server側API key、client secretの期限。
CORS errorViteのoriginとserverのCORS設定。
音が返らないbrowser autoplay/audio device、session接続状態。
古いRealtimeサンプルが動かないbeta APIではなくGAのclient_secrets / current SDKを使っているか。

6. Realtime / GPT-Live / chained pipelineを選ぶ

方式向く用途特徴
Realtime API自然なspeech-to-speech音声理解・reasoning・Toolを1sessionで扱う
GPT-Live会話を止めず別backendへ仕事を委譲voice frontとbackend reasoningを分離
STT→Agent→TTS各段階を検査・差し替えたいtranscriptやpolicy checkを挟みやすい

「一番新しい方式」を選ぶのではなく、会話自然さ、backend制御、途中textを検査したいかで選びます。

7. Toolを追加する時はbusiness logicをserver側へ残す

天気やカレンダーなどToolを足せますが、browserへcredentialや重要なbusiness ruleを置かないようにします。Voice Agentは「会話担当」、backendは「権限のある処理担当」と分離すると安全です。

8. 割り込みを試す

Agentが話している途中でユーザーが話し始め、正しくbarge-inできるか試します。音声Agentでは「返答内容が正しい」だけでなく、turn detectionやinterrupt behaviorが体験品質を大きく左右します。

9. Voice Agentの評価項目

  • 音声認識が意図を正しく取れたか。
  • 初回音声までのlatency。
  • 割り込みが成立するか。
  • Tool/delegationが正しいか。
  • backendの最終状態が正しいか。
  • Agentが結果をユーザーへ正しく伝えたか。

自然な声で「予約できました」と言っても、実際の予約が失敗していたらtaskとしては失敗です。

10. 本番へ進む前に

  • API keyはserver only。
  • client secretは短寿命。
  • 個別ユーザーがいる場合はprivacy-preservingなsafety identifierを検討する。
  • Tool side effectにapproval/validationを入れる。
  • session終了、network断、再接続を扱う。
  • 音声・transcriptの保存方針を明確にする。
  • latencyとcostを計測する。

11. 発展課題

  • 天気などread-only Toolを1つ追加する。
  • conversation transcriptを画面にも表示する。
  • Realtime版とSTT→Agent→TTS版を作り、latencyを比較する。
  • GPT-Liveでbackend agentへdelegationする。
  • AITuberの音声部分をBrowser SpeechSynthesisからRealtimeへ置き換える。
