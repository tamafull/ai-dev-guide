Glossary

用語集

AIエージェント、コンテキスト設計、MCP、評価、運用などで使う用語を短く整理しています。英語名も原典や追加情報を探しやすいよう併記しています。

受け入れ条件 Acceptance Criteria

機能を「完成」と判定するための具体的な条件です。要求が「何を作るか」なら、受け入れ条件は「何が満たされれば合格か」を示します。

例: 正しい権限の利用者は更新でき、権限がない利用者には403を返す。

停止条件 Stop Criteria

AIが自力で作業を続けず、人間へ判断を返す条件です。権限不足、予算超過、同じ失敗の反復、仕様矛盾などを事前に決めます。

セキュリティ条件 Security Criteria

機能要件とは別に、安全性について満たすべき条件を明文化したものです。認証、認可、入力検証、秘密情報、外部通信などが対象です。

実行基盤（ハーネス） Harness

AIモデルの周囲で、ツール、権限、コンテキスト管理、再試行、監査、検証などを提供する仕組みです。実務ではモデル単体ではなく、この実行基盤を含めた全体で性能と安全性を評価します。

コンテキスト設計 Context Engineering

AIへ何を、いつ、どの形式で渡すかを設計することです。大量の情報を常時投入するのではなく、目的に必要な情報へ絞ることを重視します。

ツール探索 Tool Search

利用可能なツールをすべて最初から見せるのではなく、必要な場面で候補を探して読み込む仕組みです。ツール定義によるコンテキスト消費を減らせます。

MCP Model Context Protocol

AIアプリケーションから外部ツールやデータへ接続するためのプロトコルです。ツール、リソース、プロンプトなどを共通の形で公開・利用できます。

エージェント型ワークフロー Agentic Workflow

AIが1回の回答だけで終わらず、調査、ツール実行、修正、検証を複数回繰り返して目的達成を目指す処理の流れです。

正解判定基準（テストオラクル） Test Oracle

テスト結果を正しいかどうか判断する基準です。AI実装では、実装したAI自身と独立した正解判定基準を持つことが重要です。

非公開検証テスト（ホールドアウトテスト） Holdout Test

実装するAIが内容を直接見ない検証用テストです。見えているテストだけに過剰適合することを防ぐために使います。

機能許可リスト Capability Allowlist

AIが使える能力を、必要なものだけ明示的に許可する方式です。ファイル書き込み、ネットワーク、認証情報、MCP、CIなどを別々に扱います。

実行履歴 Trajectory

AIがタスク中に行った推論上の節目、ツール呼び出し、ファイル変更、失敗、再試行などの流れです。監査では最終回答だけでなく、この履歴を確認します。

可観測性 Observability

AIの処理状況や失敗原因を外部から追えるようにする考え方です。モデル呼び出し、ツール操作、CI、PR、コストなどを関連付けて追跡します。

プロンプトキャッシュ Prompt Cache / Prefix Cache

何度も使う同一または共通の入力部分を再利用し、処理時間やコストを減らす仕組みです。製品によって名称や条件が異なります。

コンテキスト圧縮 Context Compaction

長くなった会話やツール出力を短く整理し、重要情報を残しながらコンテキスト量を減らす処理です。圧縮で重要な詳細を失う危険もあります。

再開可能な実行 Durable Execution

長時間処理が途中で止まっても、保存済みの状態から安全に再開できるようにする設計です。外部操作の二重実行を防ぐ仕組みも含みます。

モデル振り分け Model Routing

作業の難しさ、速度、コストなどに応じて使用するAIモデルを切り替えることです。すべてを最高性能モデルへ投げるより、総コストを下げられる場合があります。

成功1件あたりの総消費量 Success per Total Usage

単純なトークン量ではなく、再試行、ツール実行、検証、人間レビュー、手戻りまで含めて、成功した作業1件にどれだけ資源を使ったかを見る考え方です。
