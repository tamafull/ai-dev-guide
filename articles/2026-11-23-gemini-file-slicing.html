PDFや表計算は全部読ませず、必要な範囲だけ高解像度で見る

長いPDFやスライドを毎回まるごと画像として渡す必要はありません。Gemini APIのfile slicingでは、ページ範囲、シートとセル範囲、動画・音声の時間区間、抽出するレイヤーや解像度を指定し、必要な部分だけをモデルへ渡せます。

「全文を読む」から「安く全体を探し、必要箇所だけ拡大する」へ

2026年11月23日、GoogleはGemini APIにserver-side file slicingを追加しました。Files APIへ一度アップロードしたファイルURIを複数のリクエストで再利用し、最初はPDFの抽出テキストや低解像度の情報で対象ページを探し、次にグラフや脚注があるページだけ高解像度の画像として確認できます。

ドキュメント・スライドでは start_page / end_page と page_text / page_image を選べます。表計算では sheet_index と visible_cells、動画では開始・終了時刻、fps、解像度、transcript / frames / audioなどのcontent layerを指定できます。

実装イメージ

同じPDF URIを使い、1回目は全文のテキストレイヤーだけで対象ページを探し、2回目はそのページ画像をhigh resolutionで読みます。ファイル全体を再アップロードする必要はありません。

from google import genai

client = genai.Client()
doc = client.files.upload(file="quarterly_report.pdf")

# 1. 全ページの抽出テキストから、目的のページを探す
skim = client.interactions.create(
    model="gemini-4-hydrogen",
    input=[
        {
            "type": "document",
            "uri": doc.uri,
            "mime_type": doc.mime_type,
            "processing": {
                "type": "static",
                "page_options": {"content_layers": ["page_text"]},
            },
        },
        {
            "type": "text",
            "text": "売上のrevenue bridge chartがあるページ番号と見出しを答えて。",
        },
    ],
)
print(skim.output_text)

# 2. 返されたページ番号を使い、必要なページだけ画像として読む
page = 3  # 1-indexed。skimの結果に合わせて変更する

detail = client.interactions.create(
    model="gemini-4-hydrogen",
    input=[
        {
            "type": "document",
            "uri": doc.uri,
            "mime_type": doc.mime_type,
            "resolution": "high",
            "processing": {
                "type": "static",
                "page_options": {
                    "start_page": page,
                    "end_page": page,
                    "content_layers": ["page_image"],
                },
            },
        },
        {
            "type": "text",
            "text": "このページのグラフの数値、注記、脚注を読み取り、本文の説明と矛盾がないか整理して。",
        },
    ],
)
print(detail.output_text)

必要なパッケージは pip install --upgrade google-genai。Google AI StudioでGemini API keyを作り、環境変数 GEMINI_API_KEY に設定します。コードはGoogle公式のPython SDK例を基にしています。

解像度とcontent layerを使い分ける

  • page_text: 見出し、本文、抽出可能な文字を探す。全体のスキャンに向く。
  • page_image: 図表、レイアウト、脚注、画像内文字を確認する。必要なページだけhigh resolutionへ上げる。
  • low / medium / high: 公式ドキュメントの目安では、ページ画像のtoken量はlowが約280、mediumが約560、highが約1,120 token/ページ。
  • spreadsheet: sheetとcell rangeを絞り、data・formulas・visualsのどれを読むか指定する。

Geminiは指定したsliceだけをtoken計上・課金対象にします。Files APIへアップロードするファイル自体のサイズ・ページ上限は残るため、無制限に大きな資料を送れるという意味ではありません。

正常確認と失敗時の見方

  • 最初の出力に、探しているページ番号と見出しが出る。
  • 2回目の出力が指定ページのグラフや脚注を根拠に説明している。
  • ページ番号は1始まり。0以下はinvalid argument、ファイル末尾より先の範囲は空のsliceになり得る。
  • end_page は start_page 以上にする。
  • グラフが読めないときはpage_imageとhigh resolutionを指定し、テキスト抽出だけで判断しない。

Files APIのアップロードファイルは48時間保存されます。機密文書を扱う場合は、アップロード先、組織のデータ取扱条件、削除・保存の要件を確認してください。

どこまで使うべきか

ファイルが小さく、質問が単純なら全文を一度送る方が簡単です。大きな資料、複数回質問する資料、図表が一部にしかない資料では、skim → zoomの方がcontextとtokenを制御しやすくなります。検索で見つけたページが正しいとは限らないため、該当ページの前後や脚注を追加確認する評価も残します。

このAPI機能はGemini API / Google AI Studio / Gemini platform向けです。一般向けGeminiアプリに同じ処理設定があるという意味ではありません。
