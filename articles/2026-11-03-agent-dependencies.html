AI用Skillも依存関係として更新する時代になった

外部から取り込んだSkill、プロンプト、指示ファイルを手動コピーして放置すると、更新の把握も変更の監査も難しくなります。Agent Package Manager（APM）で管理する依存関係なら、GitHub Dependabotの更新PRを利用できるようになりました。

更新の仕組み

2026年11月3日、GitHubはDependabotのAPM version updates対応を発表しました。apm.ymlに宣言した対応Git依存関係を確認し、更新PRを作成します。apm.lock.yamlがあれば再生成します。GitHub.comの全プランで一般提供、GitHub Enterprise Serverでは3.24から対応予定です。

既存のDependabot設定へ、APM manifestがあるディレクトリを追加します。例えばリポジトリ直下にapm.ymlがある場合は次のようにします。

version: 2
updates:
  - package-ecosystem: "apm"
    directory: "/"
    schedule:
      interval: "weekly"

この設定は既にAPMで管理しているリポジトリ向けです。APMを導入していない環境でこの設定だけを追加してもSkillが自動登録されるわけではありません。依存関係の宣言方法はAPMの公式資料を確認してください。

更新PRを自動マージしない理由

Skillや指示ファイルは単なるドキュメントではありません。Agentのツール使用方法、コマンド、外部通信、権限要求を変えられます。更新PRでは差分を読み、実行コマンド、外部URL、credential参照、指示の優先順位が変わっていないか確認します。重要なSkillでは固定fixtureによる動作確認も行います。

今回の対応はバージョン更新のみで、Dependabotのセキュリティ更新や悪意あるSkillの自動検知を意味しません。更新PRの存在だけを安全性の保証にしないことが重要です。

導入を検証する

  1. テストリポジトリにAPM manifestと対応するGit依存関係を用意する。
  2. .github/dependabot.ymlに上記設定を追加する。
  3. Dependabotのversion updatesを有効化し、更新PRが作成されるか確認する。
  4. PRのmanifest・lockfile差分を確認し、Skillの評価ケースを実行してからマージする。

GitHub側の実行時期や対象依存関係の詳細は公式仕様に従います。手元でAPM更新PRの生成まで実証した結果ではありません。
