AGENTS.mdは“正解率を上げる魔法”ではない。288回の実験で見えた本当の使いどころ

AGENTS.mdやCLAUDE.mdを書けば、コーディングエージェントの実装正解率がそのまま上がる――とは限りません。Claude CodeとCodexを使った288回の評価では、コンテキストファイルの有無や渡し方を変えても、正解率に測定可能な差は出ませんでした。実務では、これらのファイルを「モデルを賢くする文章」ではなく、リポジトリ固有のルールや作業手順を短く伝える入口として使うのがよさそうです。

実務ではこう使う

AGENTS.mdに長い設計資料を書く必要はありません。毎回守らせたいルールと、必要な詳細文書への入口だけを置きます。

# AGENTS.md

プロジェクト標準のtest / lint / type checkを使う。

既存の認証・認可方式を勝手に増やさない。詳しい規約は docs/auth.md を読む。

DB変更は旧バージョンとの同時稼働を壊さない。詳しい規約は docs/database-migrations.md を読む。

公開APIや永続データ形式を変える必要がある場合は、実装前に止まり、影響範囲を報告する。

具体的なコマンドはリポジトリごとに違います。入口ファイルには、AIが毎回推測しなくて済むよう標準コマンドだけを書きます。

Test: bundle exec rspec
Lint: bundle exec rubocop
Test: python -m pytest
Lint: ruff check .
Test: npm test
Lint: npm run lint
Type: npm run typecheck
Test: ./gradlew test
Check: ./gradlew check
Test: go test ./...
Check: go vet ./...
Test: cargo test
Check: cargo clippy --all-targets
Build: cmake -S . -B build && cmake --build build
Test: ctest --test-dir build

このファイルの役目は「難しい実装を解けるようにする」ことではなく、「誤ったテスト手順を選ぶ」「既存の認可方式を無視する」「公開APIを無断で壊す」といった、リポジトリ固有の事故を減らすことです。

個別機能の説明は別ファイルへ分けます。認可なら docs/auth.md、DB移行なら docs/database-migrations.md、API互換性なら docs/api-compatibility.md といった形です。AIには、仕事に関係する文書だけ追加で読ませます。

288回の実験では、正解率はほぼ動かなかった

REALM 2026で発表された「Do Context Files Help Coding Agents?」は、Claude CodeとCodexを対象に、3つの実リポジトリから17タスクを選び、288回の評価済みrunを比較しています。評価には実際にマージされたPR由来のgold testを使っています。

比較したのは、コンテキストファイルなし、AGENTS.md相当の情報を渡す条件、必要時に参照できる情報を用意する条件です。結果は、どちらのエージェントでもコンテキスト戦略による正解率の差を測定できませんでした。等価性検定では、差がClaude Codeで10ポイント以内、Codexで15ポイント以内に収まることを示しています。

失敗内容を調べると、主な原因はリポジトリ知識の不足ではなく、機能設計、既存パターンの選択、正確な配線といった実装能力側でした。実際のAGENTS.mdを使った追加検証でも、惜しい失敗を成功へ変えたケースは確認されませんでした。

ではAGENTS.mdは無意味なのかというと、そうでもない

この研究が否定しているのは、「AGENTS.mdを置けば実装正解率が自動的に上がる」という強い期待です。プロセス効率や保守性まで無意味だと示したわけではありません。

著者自身の補足では、あるリポジトリでClaude Codeがコンテキストファイルの指示に従って重い全テストの実行を減らし、実行時間を約24%短縮したケースが報告されています。正解率は変わらなくても、「どのテストを回すか」「何を触ってはいけないか」のような作業ルールには意味がある可能性があります。

さらにASE 2026の別研究は441リポジトリを観察し、AI向けの設定ファイルやルールをコミットしているリポジトリほど、coding agent導入後の認知的複雑度や静的解析警告の悪化が小さい傾向を報告しています。設定なしのagent-firstリポジトリでは認知的複雑度が約53%増えたのに対し、設定ありでは約27%でした。

ただし、こちらは観察研究です。設定ファイルそのものが品質を改善したとは断定できません。もともと開発規律の高いチームほど設定も整備していた、といった交絡があり得ます。

2つの研究を合わせると、役割が見えてくる

現時点では、AGENTS.mdを「難しいタスクの正解率を上げる追加知能」として期待するより、リポジトリとAIの間の運用契約として扱う方が自然です。

期待する役割現時点の見方
複雑な実装そのものを解けるようにする強い証拠はない。288-runの実験では正解率差なし。
テストやビルドの正しい手順を伝える有用な可能性がある。作業効率への効果例あり。
禁止事項や設計上の不変条件を伝える実務上の主用途として妥当。ただしCIやlintでも強制したい。
チーム全体のAI利用ルールをバージョン管理する広く採用されている。2,853リポジトリ調査ではContext Filesが最も一般的。

長く書くより、「いつ何を読むか」を書く

この結果を受けても、ガイドの「AGENTS.mdやCLAUDE.mdは百科事典ではなく入口にする」という方針は変えません。

実装能力そのものがボトルネックなら、巨大な背景説明を追加しても解決しないことがあります。それなら、常時コンテキストには毎回必要なルールだけを置き、認可やDB移行などの詳細は必要なタスクでだけ読む方が無駄が少なくなります。

たとえば「認可変更時は docs/auth.md を読む」「DB変更時は docs/database-migrations.md を読む」という入口を置き、ルール違反はCIや独自lintでも検出する。AGENTS.mdだけに安全性を背負わせない構成です。

研究の限界

288 runという規模はこの種の実験として有用ですが、対象は3リポジトリ、17タスク、2種類のエージェントです。巨大な企業リポジトリ、別言語、別モデル、非常に規約依存のタスクでは結果が変わる可能性があります。

また、441リポジトリの研究は実世界の規模が大きい反面、RCTではありません。設定ファイルの存在と品質悪化の小ささには相関がありますが、因果関係は確定していません。

2,853リポジトリの設定調査も、AGENTS.mdが広く使われていることは示しますが、それだけで有効性を証明するものではありません。普及率と効果は分けて読む必要があります。

ガイドへの反映

コンテキスト設計の詳細ページに、「AGENTS.mdは正解率を上げる魔法ではなく、リポジトリ固有ルールの入口として使う」という位置づけを反映しています。現在の「短い入口＋必要時に詳細文書を読む」という推奨自体は維持します。

根拠

  • Prakhar Khatri — Do Context Files Help Coding Agents?。REALM 2026。Claude Code / Codex、17タスク、3リポジトリ、288評価runの制御比較。
  • Denisov-Blanch et al. — A Few Pages of Markdown。ASE 2026。441リポジトリの観察研究。AI設定と品質コストの関連を分析。
