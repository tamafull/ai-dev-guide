AI活用ガイド
2026-11-23 · 開発・レビュー

AIレビューはPRの修正と承認ポリシーまで担い始めた

コード生成の次に詰まりやすいのは、レビュー指摘への対応、CI失敗の修正、承認待ちです。Claude ShipはGitHubのPRに対し、レビュー、修正、チームのルールに基づく承認判断をつなぐ仕組みを公開しました。便利さと同時に、承認権限をどこまでAIへ渡すかが新しい設計課題になります。

3つの役割は、同じ「レビューAI」ではない

  • Code Review: 複数の観点からPRを調べ、指摘を検証・分類して投稿する。Quick / Standard / Deepのreview levelをrepositoryごとに設定でき、一般提供。
  • PR Steward: CI失敗、merge conflict、Code Reviewや人間からの指摘に対応してPRを修正する。push後に変更内容と戻し方をコメントする。承認やmergeは行わない。beta。
  • Claude Approvals: repository内のpolicy fileに従い、定型変更を承認したり、人間の追加承認を要求したりする。Code Reviewの結果や自然言語で定義したclassifierなどを判断材料にできる。beta。

開発者がClaude Codeで /ship を実行すると、変更をpushしてPRを作り、レビューやCI失敗への対応を進めます。実際にmergeできるかは、実行ユーザーの権限とrepositoryのbranch rulesに従います。

自動承認は、最初から有効にしない

AnthropicはClaude Approvalsをまずobserve-only modeで動かし、人間のreviewerと判断が一致するかを確認してから、GitHub branch protectionのrequired checkへ組み込む方法を推奨しています。観察段階では判断を記録するだけで、承認は実行しません。

実運用では、docsのtypoや機械的な更新と、認証・認可・課金・個人情報・DB migrationを同じpolicyにしない方が安全です。高リスク領域は人間の承認者を必須にし、AIの判定だけでmergeできないbranch protectionを残します。

段階導入の手順

  1. 最初は1 repositoryだけを対象にする。
  2. Code ReviewのQuick / Standard / Deepを選び、月額ではなく実際のtoken利用量とPR数を確認する。
  3. PR StewardはManual modeで始め、開発者が明示的に呼んだPRだけを修正させる。
  4. Claude Approvalsはobserve-onlyで動かし、人間レビューとの不一致を集める。
  5. 誤承認・見逃し・過剰な差し戻しを評価セットにし、policyを直す。
  6. 高リスク変更に人間承認を残したまま、branch protectionで機械的に強制する。

利用条件とコスト

Claude ShipはGitHub repositoryを使うClaude Team / Enterprise向けです。Code Reviewは一般提供、PR StewardとClaude Approvalsはbetaです。利用量はtoken課金で、PR数・差分サイズ・review level・実行頻度・修正量により変わります。Code ReviewとPR Stewardには管理者がspend limitを設定できます。Claude Approvals自体に基本料金はありませんが、classifierやpolicyがCode Reviewを呼ぶ場合はその利用分が課金されます。

Zero Data Retention、HIPAA構成、customer-managed encryption keysを使う組織では利用できません。AIレビューはbugやsecurity vulnerabilityを見落とす可能性があるため、既存のテスト、branch protection、人間レビューを置き換える保証として扱わないでください。

効果の数字は、ベンダー事例として読む

Anthropicは自社Claude Codeチームで、6月から9月にmerged PRが2倍以上になり、revertされた割合が40%以上下がったと報告しています。ただしClaudeのreviewは既存のレビュー工程の一層であり、独立した比較試験ではありません。自社で導入する場合は、review時間、指摘の正確さ、再修正回数、merge後のrevert、token費用を別々に測ります。

ガイドへの反映

テストとレビューにPR review・修正・承認の役割分担を、セキュリティにobserve-onlyからbranch protectionへ進める段階導入を追加しました。
