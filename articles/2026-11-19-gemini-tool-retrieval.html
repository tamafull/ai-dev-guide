100個のTool schemaを毎回送らず、必要な時だけ読み込む

エージェントが数十〜数百のToolを持つと、各Toolのparameter schemaを毎回promptへ入れるだけでcontextとtokenを消費します。Gemini APIのTool Retrievalは、Tool名と説明を候補として残し、詳細schemaを必要になった時だけ読み込む仕組みです。

遅延ロードされるのは「parameter schema」

2026年11月19日、GoogleはInteractions APIにTool Retrievalのpreviewを追加しました。tool_searchを宣言し、後から読み込むToolへ defer_loading: true を付けると、最初のpromptにはTool名と説明だけが入り、詳細なparameter schemaは必要時に取得されます。モデルがToolを選ぶと、APIがschemaを読み込んでfunction callを返します。

これはToolそのものを自動実行する仕組みではありません。アプリ側は返されたfunction callを受け取り、認証・認可・入力検証を行ってから実処理し、function resultを返します。

最小の動作例

次の例は固定レートのデモ変換関数を使います。実際の為替レートを取得するものではありません。Gemini API keyを GEMINI_API_KEY に設定し、Python SDKを更新します。

pip install --upgrade google-genai
export GEMINI_API_KEY="YOUR_API_KEY"

from google import genai
import json

client = genai.Client(http_options={"api_version": "v1beta"})

tools = [
    {"type": "tool_search"},
    {
        "type": "function",
        "name": "convert_currency",
        "description": "Convert an amount from one currency to another using the demo rate table.",
        "defer_loading": True,
        "parameters": {
            "type": "object",
            "properties": {
                "amount": {"type": "number"},
                "from_currency": {"type": "string"},
                "to_currency": {"type": "string"},
            },
            "required": ["amount", "from_currency", "to_currency"],
        },
    },
]

interaction = client.interactions.create(
    model="gemini-4-hydrogen",
    input="Convert 100 USD to EUR.",
    tools=tools,
)

for step in interaction.steps:
    print(step.type, getattr(step, "name", ""))

call = next(s for s in interaction.steps if s.type == "function_call")
args = call.arguments
rates = {("USD", "EUR"): 0.92}
key = (args["from_currency"], args["to_currency"])
if key not in rates:
    raise ValueError(f"Unsupported demo pair: {key}")
result = {
    "amount": args["amount"] * rates[key],
    "currency": args["to_currency"],
    "rate_type": "fixed demo rate",
}

followup = client.interactions.create(
    model="gemini-4-hydrogen",
    previous_interaction_id=interaction.id,
    tools=tools,
    input=[{
        "type": "function_result",
        "name": call.name,
        "call_id": call.id,
        "result": [{"type": "text", "text": json.dumps(result)}],
    }],
)
print(followup.output_text)

実行時には tool_search_call、tool_search_result、function_call の順でstepが観察できます。最後にアプリ側で関数を実行し、function_resultを返すとモデルが回答します。検索されたschemaの詳細は interaction.steps から追跡できます。

Server-sideとclient-sideを選ぶ

Server-side retrievalはGemini側が検索するため、追加のround tripなしに1回のAPI request内でschemaを取得できます。既知のToolライブラリやremote MCP serverを多数つなぐ場合に向きます。

Client-side retrievalはアプリが検索を実行します。ユーザーごとの権限filter、namespace、独自ranking、動的なTool registryを使う場合に向きますが、検索ごとに追加のround tripが発生します。remote MCP serverもserver-sideの defer_loading: true でTool一覧を遅延ロードできます。

方式向くケース注意
Static loading少数で安定したTool（目安20未満）全schemaを毎回送る
Server-side大きな既知のTool library、MCP server検索はAPI内で行われる
Client-sideユーザー別registry、動的namespace検索処理と追加round tripが必要

tokenが必ず減るわけではない

Tool Retrieval自体に別料金はありませんが、候補名・descriptionとserver-side searchの内部呼び出しでtokenが追加され、読み込まれたschemaもinput tokenとして課金されます。検索の内部処理に使われたtokenはusageに別枠で現れます。大きなlibraryのうち実際に使うToolが少ないほど節約しやすく、小さなlibraryや毎回多くのToolを使う場合はstatic loadingの方が安いこともあります。よく使うToolは最初から読み込み、long tailだけをdeferするのが基本です。取得されたschemaは会話内へ追加され、後続turnでもContextに残り得ます。不要なschemaが増える場合は会話やsessionを切り替えるか、stateless historyを自前管理するときに履歴の範囲を設計します。

導入前後で、通常のinput token、tool-use token、latency、選択ミス、function callの成功率を同じ評価セットで比較します。Tool名とdescriptionは最初からモデルに見えるため、descriptionが曖昧だと検索対象の選び間違いは残ります。

権限は遅延ロードとは別に守る

schemaを後から読み込むことは、Toolの権限を制限することではありません。払い戻し、削除、メール送信、デプロイなどの実処理はアプリ側で認証・認可し、ユーザーごとのallowlist、承認、監査ログを維持します。検索されたToolが許可されていなければ実行せず、読み取り専用の代替を返します。

提供条件

Tool Retrievalは2026年11月時点でpreviewです。Interactions APIの v1beta が必要で、generateContentでは利用できません。対応モデルはGemini 4 Carbon / Neon / Hydrogen / Argonと、Gemini 3.8 Flash / 3.6 Flashです。preview中はAPI surfaceが変更される可能性があります。
