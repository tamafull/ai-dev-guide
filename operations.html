長時間実行と運用 · 2026-10-26

長い仕事は「会話」ではなく、再開できる作業として設計する

数時間から数日にまたがる作業では、途中状態、再試行、外部副作用、マージ後の監視まで含めて設計します。会話履歴が残っているだけでは十分ではありません。

推奨信頼度: 中〜高

長時間タスクは、小さな検証単位へ切る

巨大な「全部直して」タスクは、途中で方向を誤ったときの損失が大きくなります。調査、変更、検証を小さなまとまりへ分け、各段階で成果物を残します。

Anthropicの長時間アプリ開発事例でも、plannerが仕様をfeature/sprintへ分解し、generatorが1 featureずつ実装し、evaluatorが実際のアプリを操作して確認しています。役割数より「小さな完了単位」と「外部評価」が重要です。

作業状態はファイルやIssueへ書き出す

途中状態として残すのは、少なくとも目的、現在の計画、完了済み、未完了、失敗した試行、判断理由です。再開時に会話全文を読み直さなくても仕事を続けられる形にします。

docs/agent-task.md

Goal: 何を達成するか
Constraints: 壊してはいけないもの
Done: 完了した変更と検証
Next: 次にやること
Blocked: 人間判断が必要な点
Evidence: benchmark / test / logの保存先

再試行しても副作用が二重にならないようにする

processが落ちた後に再開したとき、同じmigration、外部API変更、通知送信をもう一度実行すると危険です。外部副作用にはoperation ID、idempotency key、状態確認を入れます。

たとえばデータ移行なら、agentがmigration codeやbatch jobを書くところまでは通常workflowで扱えても、本番実行は別jobへ分けます。job側は処理済みcursorやbatch IDを永続化し、同じbatchを二重適用しないようにします。

CI/CDはAgentの「外部判定装置」にする

AIがローカルで「通りました」と報告するだけでなく、CI側で同じ判定をやり直します。単体テスト、静的解析、security scan、リポジトリ固有policy、migration checkなどを決定論的に通します。

OpenAIのagent-first開発事例では、architecture ruleを独自lintやstructural testで強制しています。Agentにルールを覚えさせるのではなく、違反すれば機械的に落ちるようにする設計です。

11時間動かすなら、途中で何をしたか追えるようにする

可観測性の対象はモデル呼び出しだけではありません。task ID、tool call、ファイル変更、test結果、CI、PR、review、deployまでつなぎます。費用や失敗を分析するとき、どこで時間を使ったかが分かるようにします。

GoogleのADK最適化事例では、11時間のrunでbenchmark、12個のguideline file、全16,892 unit test、差分監査まで実行しています。6提案のうち4件は人間レビューで削除されました。長時間動いたこと自体ではなく、最後に何を採用したかまで追う必要があります。

本番では「検出・停止・戻す」を先に決める

  • feature flagで即時停止できるか。
  • DB変更はexpand/contractで後方互換を保てるか。
  • 異常率やlatencyを自動で検出できるか。
  • どのcommit / agent taskが原因か追えるか。
  • 自動rollbackを許す範囲と、人間承認が必要な範囲を決めているか。

性能改善のような長時間探索はAgentと相性がよいが、採用判断は別

Googleの事例では、Agentが約20.5万行のコードベースで性能ボトルネックを探索し、6つの最適化案を出しました。最終的に採用されたのは2つです。別のMicroPerf-Benchでは、9つのagent/model構成を1,755 runで評価し、最良でも注入した性能劣化の42%しか回復できませんでした。

Agentは探索量を増やせますが、system-levelの因果を正しく突き止めるのはまだ難しいです。benchmarkやproduction telemetryで効果を測り、「コードがもっともらしい」だけでは採用しません。

根拠

  • Anthropic — Harness design for long-running application development。長時間app開発のmulti-agent harness事例。
  • Google — ADK 11時間最適化事例。6提案中2件採用。ベンダー事例。
  • OpenAI — Harness engineering。CI、custom lint、structural testでagent-generated codeを制御。
