Editorial Style Guide

人間が読みやすいガイドにする

このページは、今後の自動更新でも守る執筆規約です。Google、Microsoft、GOV.UK系の技術文書・Webコンテンツ指針を参考に、AI開発ガイド向けに整理しています。

最重要ルール

  1. 結論を先に書く。 読者が最初の数行で「何をすべきか」を判断できるようにします。
  2. 見出しだけ読んでも内容が分かるようにする。 「セキュリティ」より「権限制御はAIの外側で強制する」のように書きます。
  3. 1段落を短くする。 1つの段落に複数の論点を詰め込みません。
  4. 1つの概念には1つの用語を使う。 同義語を装飾目的で使い分けません。
  5. 日本語で通じる用語は日本語を先に書く。 英語は初出・検索用に併記します。

1. 最も重要な情報を先に置く

Web上の文章は、最初から最後まで精読されるとは限りません。各ページ、各節、各段落の先頭に、その部分で最も重要な情報を置きます。

このガイドでの書き方

推奨: 「結論: 本番用認証情報はAIへ直接渡さない。短命で用途限定の認証情報を使う。」
避ける: 背景説明を数段落続けた後に、最後の一文で結論を書く。

根拠: Microsoft Style Guide は「Put first things first」、GOV.UK/ONS系のcontent guidanceはfront-loadingと逆ピラミッド型の構成を推奨しています。

2. 見出しを「内容の要約」として書く

読者は本文より先に見出しを走査します。そのため、見出しはカテゴリ名だけではなく、できるだけ結論や行動を含めます。

弱い見出し読みやすい見出し
Security権限制御はAIの外側で強制する
Testingテストは実装から独立させる
Cost安さは成功1件あたりで測る

根拠: Microsoftは、見出しを走査可能な情報の目印として使い、具体的で短い見出しにすることを推奨しています。

3. 短い文章と短い段落を使う

長い一文に条件、例外、理由、結論を詰め込みません。必要なら2文以上に分けます。

  • 1段落は原則として1論点。
  • 段落が画面上で長く見える場合は、見出しや箇条書きへ分解。
  • 手順は番号付きリスト、並列な項目は箇条書きを使う。
  • 主語と動作が分かる能動的な文を優先。

Googleの技術文書ガイドは短い文、段落の分割、重要情報の先頭配置を推奨しています。Microsoftも短い見出し・文・段落による走査性を重視しています。

4. 「推奨 → 理由 → やること → 注意」の順で書く

各実務指針は、できるだけ同じ型に揃えます。ページごとの読み方を学び直さなくて済むからです。

推奨
何をすべきかを1〜2文で示す。
理由
なぜ必要なのかを短く説明する。
実務でやること
具体的な行動を箇条書きにする。
注意
誤解しやすい点、適用しない条件を書く。
根拠
必要に応じて研究・一次情報へリンクする。

5. 用語は日本語を主表記にする

日本語として自然に通じるものは日本語を主にします。英語だけの見出しを増やしません。

旧表記このガイドでの表記
Workflow開発の進め方
Specification仕様定義
Context Engineeringコンテキスト設計
Agent Architectureエージェント構成
Testing & Reviewテストとレビュー
Acceptance Criteria受け入れ条件（Acceptance Criteria）
Stop Criteria停止条件（Stop Criteria）
Observability可観測性（Observability）
Capability Allowlist機能許可リスト（Capability Allowlist）

MCP、API、CI/CDのように略称そのものが識別子として重要な用語は、無理に置き換えず説明を添えます。詳しくは用語集を参照してください。

6. 詳細は別ページへ分ける

トップページには「現在何をすべきか」を置きます。用語の定義、根拠、長い比較、過去の経緯は別ページへ分けます。

  • トップ: 現在の推奨と実務手順
  • 用語集: 定義と関連語
  • 根拠: 論文・独立研究・ベンダー一次情報
  • 更新履歴: いつ、なぜ推奨を変更したか
  • 保留: 興味深いが未採用の知見

GOV.UKのcontent design guidanceも、大きなコンテンツを必要に応じて小さい単位へ分割し、重複や過剰な情報を減らすことを推奨しています。

7. アクセシビリティを文章構造に含める

  • 各ページの主見出しは1つのH1にする。
  • H2→H3の順序を崩さない。
  • リンクは「こちら」ではなく、リンク先が分かる文言にする。
  • 色だけで「推奨」「注意」を区別しない。
  • 略語は初出で説明する。

Googleは、短い文、見出し、リスト、略語の初出説明、左揃えなどを読みやすさ・アクセシビリティの観点から推奨しています。

8. 自動更新でもこの規約を守る

隔日の調査で新知見を追加するときも、単に情報を追記しません。現在の結論が変わる場合は本文を更新し、背景は根拠ページと更新履歴へ移します。

品質チェック: 更新後に「最初の画面だけで要点が分かるか」「見出しだけで内容を追えるか」「日本語にできる用語が英語のまま残っていないか」を確認します。
